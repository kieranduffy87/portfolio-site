01
Scroll scrubSplit text3D transforms

Kinetic Type

Type as choreography

A scroll-scrubbed typographic sequence. Every character is an independent actor on one timeline: it rises, rotates in 3D, settles, then hands over to the next line while a difference-blend bar sweeps the seam.

How it works. No libraries. One scroll-progress value drives per-character transforms with staggered sub-timelines.

02
Cursor physicsSpringsHover states

Magnetic

Interfaces that pull back

Cursor physics: buttons that attract as you approach, cards that tilt with a specular highlight tracking the pointer, and list rows that fill upward on hover. Every value is integrated per frame, so nothing snaps.

How it works. A single rAF loop lerps every element toward its target. Pull strength falls off with distance from centre.

03
WebGLGLSLGenerative

Aurora

Colour that breathes

A live WebGL gradient with no images at all: fractal noise, domain-warped twice, pushed through a brand palette and steered by the pointer. Runs on a single fullscreen triangle.

How it works. Hand-written fragment shader (fbm + domain warping). Falls back to an animated CSS field where WebGL is unavailable.

04
Hover revealInertiaVelocity skew

Reveal

An index that shows its hand

The agency-list problem: a list scans faster than a grid but hides the work. Here the preview tracks the cursor with inertia, skewing to its own velocity, while the rest of the index dims away.

How it works. Preview position lerps behind the pointer; frame skew and scale are derived from per-frame delta.

05
Pinned scrollHorizontalParallax

Horizon

Scroll down, travel sideways

A pinned viewport that maps the vertical gesture people already know onto a horizontal cinema, with per-panel parallax depth and a skew that reads scroll speed.

How it works. Sticky section plus one transform on the track. Panels offset by depth factor and distance from centre.

06
Scroll sequenceBrand motionChoreography

Unfold

The mark becomes the interface

A brand reveal as a scroll sequence: the two halves of the KD mark fly in and lock, the assembled mark shrinks up into the navigation, and the landing page composes itself in its wake.

How it works. One progress value split into overlapping windows, each easing a different element of the page into place.

Why bother?

Because the fastest way to understand an interaction is to build it. Everything here started as a question: what does scroll feel like moving sideways, what makes a hover feel physical, how much can a single shader carry. The answers end up back in client work, which is the real point.
